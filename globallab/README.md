# globallab 仕様書

グローバルラボ（黒い砂漠のテストサーバー）の週次アップデート告知が新しく出たら、
タイトルと原文 URL を Discord に投稿するツール。

導入手順は [リポジトリの README](../README.md#グローバルラボ更新通知globallab) を参照。
この文書は「どう動くか」「なぜそうしたか」を書く。

## 構成

| ファイル | 役割 |
|---|---|
| `globallab/notify.py` | 本体。Python 標準ライブラリのみ |
| `globallab/state.json` | 状態ファイル。初回実行時に作られる（配布元には置かない） |
| `.github/workflows/globallab.yml` | 毎時の定期実行と、状態ファイルのコミット |

## 処理の流れ

1. Secret `GLOBALLAB_WEBHOOK_URL` が未設定なら、何もせず正常終了する
2. 一覧ページを取得し、記事番号とタイトルを抜き出す
3. `state.json` が無い（初回）なら、最新の記事番号を記録して終了する。投稿はしない
4. 記録済みの番号より大きい記事を、番号の小さい順に処理する
   - 投稿対象なら Discord に投稿する
   - 対象外でも番号は進める
5. 番号が進んだら `state.json` を保存し、ワークフローがコミットする

## 取得元

```
https://blackdesert.pearlabyss.com/GlobalLab/en-US/News/Notice?_categoryNo=2
```

- RSS は無い。一覧は JavaScript なしの HTML で返り、記事リンクが直接書かれている
- `_categoryNo=2` は「Updates」タブ。週次の告知とセキュリティモジュール更新の告知が混在する
- 英語版（en-US）のページでも、タイトルは韓国語のまま

### HTML の構造（2026-09-29 に実物で確認）

```html
<a class="board_item_inner" href="https://.../News/Notice/Detail?_boardNo=19861" data-boardno="19861">
  ...
  <p class="title line_clamp">9&#xC6D4; 28&#xC77C;(&#xC6D4;) ...</p>
  <div class="info">
    <span class="info_item thum_cate category_2">Updates</span>
    <span class="info_item date">Sep 28, 2026 (UTC+3)</span>
  </div>
</a>
```

- 同じ記事が**上部スライダー**（`a.news_item`、数件）と**本体一覧**（`a.board_item_inner`）の2か所に出る
  → 記事番号で重複を除く
- `<a>` の中にはタイトル以外にカテゴリ名と日付がある
  → `class` に `title` を含む要素のテキストだけを読む
- タイトルは HTML 数値参照（`&#xC5C5;` など）で書かれている
  → `html.parser` の既定動作（`convert_charrefs=True`）で文字に戻るため、特別な処理はしない。
  生の HTML に対して「업데이트 안내」を文字列検索しても見つからない点に注意
- 1ページに 24 件（本体一覧）

### 記事番号（`_boardNo`）

- 記事ごとの連番 ID。新しい記事ほど大きい
- **連続はしない**（飛び飛びになる理由は未確認）。
  2026年7月上旬には 13393 → 19540 と大きく飛んでいる。大小比較だけで判定しているので影響はない
- 記事を編集してもタイトルに「(최종 수정 : …)」が付くだけで、番号は変わらない → 二重投稿にはならない

## 投稿対象の判定

タイトルが次の両方を満たすもの：

- 「**업데이트 안내**」（アップデートのお知らせ）を含む
- 「**보안 모듈**」（セキュリティモジュール）を含まない

カテゴリ指定が効かず全カテゴリの一覧が返ってきた場合でも、この判定で弾ける前提。
条件は `notify.py` の `INCLUDE` / `EXCLUDE` で変えられる。

2026-09-29 時点の一覧 24 件での判定結果：投稿 18 件、除外 6 件（すべて「보안 모듈 최신 버전 업데이트 안내」）。

## 投稿内容

```
📢 **グローバルラボ更新**
9월 18일(금) 업데이트 안내
https://blackdesert.pearlabyss.com/GlobalLab/en-US/News/Notice/Detail?_boardNo=19837
※原文は韓国語です。ブラウザの翻訳機能で読めます。テスト鯖の情報のため、日本鯖への適用時期・内容は未定です。
```

- **翻訳はしない。** 機械翻訳・LLM 翻訳・外部の用語データベースはどれも使わない。
  原文 URL を渡し、中身はブラウザの翻訳機能で読んでもらう
- **リンクの埋め込みプレビューは出さない**（Discord の `flags: 4` = SUPPRESS_EMBEDS）。
  公式の OGP は汎用の画像とタイトルで、情報にならないため
- URL は取得元に合わせて en-US 版

## 状態ファイル

`globallab/state.json`

```json
{
  "last_board_no": 19861
}
```

| キー | 意味 |
|---|---|
| `last_board_no` | 処理済みの最大の記事番号。これより大きい記事を新着とみなす |
| `error_notified` | 取得失敗の警告を投稿済みなら `true`。取得に成功すると消える |

- 初回実行では投稿せず、現在の最新番号を記録するだけ（過去分の一斉投稿を防ぐ）
- 番号を小さく書き換えて手動実行すれば、その間の告知が再投稿される（動作確認用）

## 異常時の動き

| 状況 | 動き | ワークフロー |
|---|---|---|
| Secret 未設定 | 何もしない | 成功 |
| 一覧の取得・解析に失敗（記事0件も含む） | 投稿先に警告を**一度だけ**出し、`error_notified` を立てる。以降は黙る | 成功 |
| 取得失敗の後に復旧 | `error_notified` を消し、通常運転に戻る | 成功 |
| 投稿に失敗（Webhook 削除・一時障害） | その記事の手前で止め、番号を進めない。次回に再試行 | 成功 |
| 警告の投稿にも失敗 | `error_notified` を立てない（次回また警告を試みる） | 成功 |

**ワークフローを失敗扱いにしない理由**：失敗扱いにすると、リポジトリのオーナーに毎時失敗メールが届く。
異常は投稿先チャンネルで気づける設計にしてある。

**Webhook を削除すれば止まる理由**：投稿が失敗し続けるだけで、ワークフローは成功で終わる。
リポジトリ側の操作は不要。

## 実行

- 毎時 17 分（UTC）。告知が無い週もあり、その場合に何も投稿されないのは正常
- `concurrency: globallab` で、同じツールの実行が重ならないようにしている
- `state.json` のコミットの前に `git pull --rebase` する（他のツールが同時にコミットした場合への備え）
- 公開リポジトリは 60 日間動きがないと定期実行が止まる。新着のたびに `state.json` がコミットされるので、その延命も兼ねる

## ローカルでの確認

```
python globallab/notify.py --dry-run               # 投稿・状態保存をせず、一覧の判定結果を表示
python globallab/notify.py --dry-run --since 19800 # 記事番号 19800 より後だけ表示
```

## 未検証

- GitHub Actions 上での実行と、Discord への実際の投稿は、この文書を書いた時点では未確認
- ワークフローによるコミットが、60 日ルールの「動き」として数えられるかどうか
- 公式サイトの HTML 構造は予告なく変わりうる。変わった場合は取得失敗の警告で気づく想定だが、
  告知タイトルの書き方が変わる（「업데이트 안내」を含まなくなる）などの壊れ方では、
  記事は正常に取れているため警告が出ず、黙って投稿が止まる
