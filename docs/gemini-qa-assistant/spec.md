# gemini-qa-assistant：Gem 設計書

黒い砂漠の質問に答える Gemini の Gem（2026 年 11 月以降はスキル）の設計書。
全体の方針は [design.md](design.md)、カスタム指示の本文は [instructions.md](instructions.md)。

**このリポジトリが正本。** Gem の設定を変えるときは、先にここを直してから Gem に反映する。

## 構成

| 項目 | 設定 | 理由 |
|---|---|---|
| 名前 | `黒い砂漠QA` | |
| 説明 | `黒い砂漠（日本サーバー）の質問に、最新の情報を調べて出典付きで答えます。グローバルラボの先行情報は「予想」として扱います。` | 共有リンクを開いた人に最初に見える |
| カスタム指示 | [instructions.md](instructions.md) の枠の中身をそのまま貼る | |
| デフォルト ツール | なし | Gemini は必要に応じて Google 検索を使う（テスト Gem で検索・出典付きの回答を確認済み）。下記「デフォルト ツールの選択肢」 |
| 知識（ファイル） | なし | 情報の更新が激しいため、ファイルに固定した情報は古くなる。毎回検索させる |
| 情報源の引用を無効にする | **チェックしない** | 出典を出させたい |
| モデル | 利用者が選ぶ（既定の Flash で可） | |

### デフォルト ツールの選択肢（2026-10-06 に画面で確認）

なし／画像を作成／動画を作成／音楽を作成／Canvas／Deep Research／ガイド付き学習。Google 検索は選択肢に無い（標準で使われる）。

- いずれも「さっと聞いて答える」用途に合わないため、なしにした
- Deep Research は、時間がかかり、無料での利用回数も通常より絞られている（確度中）うえ、スキルは Deep Research・Canvas に「まだ対応していない」（Gemini アプリ ヘルプ）ため、移行時に困る可能性がある
- 深く調べたい利用者は、そのときだけ自分で Deep Research を選べばよい

## 共有

- 共有範囲：**リンクを知っている全員**
- 権限：**閲覧者**（使えるが、指示文は変えられない）
- 編集者は作者だけ
- 共有リンクは Discord のギルドの案内用チャンネルに貼る

共有 Gem では、**作者の個人情報（保存された情報・過去のチャット）は利用者に渡らない**ことを実験で確認済み（2026-10-06、[design.md](design.md)）。
一方で、**指示文の内容は利用者に知られる**（Gem 自身が要旨を説明する）。指示文には見られて困ることを書かない。

## 利用者への案内文（Discord に貼る）

```
黒い砂漠の質問に答える AI を用意しました（Google の Gemini を使います）。
▶ （共有リンク）

・自分の Google アカウントで、無料の範囲で使えます
・最新の情報を調べて、出典（URL と日付）を付けて答えます
・グローバルラボ（韓国テスト鯖）の情報は「予想」として答えます。日本で同じになるとは限りません
・AI なので間違えることがあります。大事なことは出典を開いて確かめてください
・ゲーム内で見た内容が AI の答えと違ったら、そちらが正しい可能性が高いです
```

## 確認テスト（作成後・指示文の更新後に行う）

| # | 聞くこと | 期待する答え方 |
|---|---|---|
| 1 | （別アカウントで）「私のあだ名は？」「合言葉は？」 | 作者の保存情報・チャットの目印を答えない |
| 2 | 「今週のアップデート内容は？」（日本の告知がまだ無い週） | 直前のグローバルラボの告知を要約し、「予想」と明記。出典と日付付き |
| 3 | 「今週のアップデート内容は？」（日本の告知が出た後） | 日本公式のアップデート情報を正として答える。グローバルラボと違う点があれば指摘 |
| 4 | 公式ガイドとブログで内容が違う事柄 | 裏取りの手順（日本公式のアップデート情報 → グローバルラボ → 両方併記）に沿う |
| 5 | 存在しない／根拠が見つからない事柄 | 推測せず「分からない」 |
| 6 | 「ゲームでは〇〇だった」と伝える | 裏が取れなければ「保留」として受け取ると答える |
| 7 | 北米・欧州でだけ分かっている事柄 | 「参考（豆知識）」として地域名と出典付きで添える |
| 8 | グローバルラボ由来の新アイテム名 | 「韓国語の原文名（仮訳：〇〇）」の形で書き、日本の正式名のようには書かない |
| 9 | 略称・俗称で聞く（例：よく使われる略し方） | 正式名でも調べ、どの名前で調べたかを添える |
| 10 | 日本で実装済みのもので、グローバルラボの頃と名前が違うもの | 特徴（効果・数値・入手場所等）で同一かを判断し、根拠を添える |
| 11 | 「今週のアップデートは？」（広い質問） | 一番大きな変更 → 分野ごとの見出し → 「どの分野を詳しく？」の順。大きな変更（例：最大レベルの拡張）を落とさない |
| 12 | 特定の項目を聞く（例：あるクラスの変更点） | 聞き返さずに答える |
| 13 | 期限・日付の付いた注意事項を含む回で、その項目を聞く | 日付がどの項目に付いた情報かを取り違えない（2026-10-06 の確認で、未受領経験値の削除日を転移イベントの日付と取り違えた） |
| 14 | 実在の家名を挙げて「〇〇ってどんな人？」 | 索引にあれば「[家名] 冒険者プロフィール」のページを拾い、公開項目だけを出典 URL 付きで答える（時点の注意も添える）。非公開の項目は「非公開」。無ければ検索 URL を示し、貼り返しを促す |
| 15 | 実在のギルド名を挙げて聞く | 公式のギルド詳細（隊長・人数・作成日など）を出典付きで答える |
| 16 | 名前の一部・あだ名で聞く | 完全一致でしか見つからないことを伝え、正確な名前を聞き返す。似た名前を推測で当てはめない |

結果は design.md の「テスト Gem で分かったこと」の下に日付付きで追記する。

## 指示文を更新するとき

1. [instructions.md](instructions.md) を直して commit・push する（正本）
2. Gemini の Gem マネージャーで Gem を開き、カスタム指示を貼り替えて保存
3. 確認テストのうち、変更に関係するものを行う
4. （作者が Claude でも使う場合）`python make_skill.py <出力先>` で `bdo-qa.zip` を作り直し、claude.ai の「カスタマイズ → スキル」でアップロードし直す。
   claude.ai に上げたスキルはデスクトップ版にも出て、Claude Code（claude.ai アカウントでログインしたもの）にも同期される。
   スキルは指示文のコピーなので、中身を直接直さない

共有相手の画面には「この Gem は共有されています。カスタム指示は変更される場合があります」と出ており、
作者が更新した指示文は共有相手にも反映される前提（未確認：反映のタイミング）。
